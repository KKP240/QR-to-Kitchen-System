เส้นทางการทำงาน

API เป็น Lambda Function URL แยกจากเส้นทาง static website

01 / GUEST ORDER

ลูกค้าสแกน QR

QR → CloudFront/S3 → Browser → Function URL → API Lambda → DynamoDB
ส่งเลขโต๊ะกับ menu item IDs; API ตรวจโต๊ะ/เมนูและคำนวณราคา แล้วคืน order ID กับ token สำหรับติดตาม

02 / STAFF OPERATIONS

ครัวและผู้จัดการ

Browser → /auth/login → JWT → API Lambda
Kitchen poll ออเดอร์และอัปเดตสถานะ; Manager ดูแลเมนู โต๊ะ และ QR โดยใช้ role checks ใน API

03 / BOOTSTRAP

เริ่มต้นข้อมูล AWS

AWS CLI (voclabs) → Seed/CreateAdmin Lambda → DynamoDB
ใช้ LabRole เขียนข้อมูลแทนเครื่อง local; helper ไม่มี public URL และไม่อยู่ใน user request path

การยืนยันตัวตน

Function URL เปิดรับ request ได้ที่ระดับ AWS (`AuthType: NONE`) แต่ API ตรวจ JWT/role สำหรับ staff endpoints; ลูกค้าสั่งจาก QR แบบ guest และติดตามออเดอร์ด้วย token เฉพาะรายการ ไม่ได้ใช้ Cognito

การอัปเดตหน้าครัว

ใช้ polling จาก browser ไป `GET /orders` ประมาณทุก 3 วินาที ไม่ได้ใช้ WebSocket; `Connections` table จึงเป็น resource ที่เตรียมไว้เท่านั้น

ข้อจำกัด Learner Lab

ใช้ `us-east-1` และ role `LabRole`; credentials ฝั่ง AWS CLI หมดอายุตาม Lab session ส่วน resource/data อาจอยู่ต่อหรือถูก reset ตามสถานะ Lab
